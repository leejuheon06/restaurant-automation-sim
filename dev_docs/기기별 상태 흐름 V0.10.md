## 읽는 법

상자는 해당 대상이 일정 조건을 유지하는 상태이고, 화살표는 사건 \[조건\] / 효과입니다. 사건은 업무 의미의 설계명이며 확정된 ROS2 메시지·API 이름이 아닙니다. 그림의 짧은 라벨은 바로 아래 전체 전이표와 함께 읽습니다.

검은 원은 초기 진입이며 사건·조건 없이 기본 상태로 진입합니다. 이중 원은 해당 유한 업무 객체의 완료입니다. 마름모는 확인이 끝난 뒤 즉시 조건을 평가하는 choice이며 응답을 기다리는 대기 상태가 아닙니다. 조건이 미충족·불명이면 보류합니다.

보류·실패와 취소 확정, 기기 복구와 업무 재개, 실제 전달과 로봇 복귀·충전·새 임무 가용을 구분합니다. 완료한 동작을 상태 진입으로 자동 재실행하지 않습니다. 연결 상실·관측 불명은 실제 물리 정지 또는 장비 고장의 증거가 아닙니다.

## 계층과 보강 범위

기존 STA 14개와 ERR 11개를 유지합니다. 기존 전이 55개의 출발·사건·조건·도착을 보존하면서 정상 보류 해제, 관측 연결 상실, 정상 운용 중 보류 적용을 각 모형에 3개씩 추가한 64개 전이의 설계안입니다. 실제 인터페이스·확인 제공자·권한 정책을 확정한 구현 결과가 아닙니다.

관측 근거 있음 상위 상태는 INITIALIZING·정상 운용·HOLDING·FAULT\_HANDLING·RECOVERY\_CHECK·OUT\_OF\_SERVICE를 실제 하위 상태로 포함하는 UML composite입니다. UNKNOWN/OFFLINE은 바깥에 있습니다. 두 상위 상태는 새 STA 코드나 병렬 운용 허용이 아닙니다.

관측 보고는 지정된 하위 상태로 직접 진입하며 묵시적 초기화·물리 동작 재실행을 하지 않습니다. T03/T10의 정상 운용 경계 진입은 내부 기본 진입을 통해 IDLE로 이어집니다. 같은 사건에 더 안쪽의 적용 가능한 전이가 있으면 그 전이가 우선합니다. 기존·신규 연결 상실/보류 진입 모두 기록 보존 효과를 명시했습니다.

보류 해제는 실제 기기 대기·해제 허용 근거가 확인될 때만 IDLE로 반영합니다. 물리 동작 기기는 실제 정지·물건 위치도 확인합니다. 기존 업무 재개·재배정은 별도 판단입니다. 기록 보존 효과를 모터 정지 명령이나 정지 완료 증거로 해석하지 않습니다.

## 단말·서버 · 각 기기별 공통 관측 모형

대상: 각 단말·서버 1기기

대표 부분도: 기존 경로와 신규 보강3전이 및 연결회복T05 표시; 전체 전이·효과는 본문표

UNKNOWN/OFFLINE≠물리 정지. 복구 후 IDLE은 기기 재가용이며 업무 자동 재개 아님.
운용 제외도 영역 완료가 아니므로 final 없음. 직접 하위상태 진입은 관측 근거 확인 경로.
상위 운용 중은 신규 STA가 아닌 하위 상태의 합; 병렬 동작 허용을 정의하지 않음.
대표 전이 축약도: 생략한 관측·복귀 전이의 원문은 JSON/대응표 보존. 최종 코드표와 함께 읽음.
직접 하위진입: UNKNOWN → OPERATING : 상태 보고 \[현재 하위 상태 근거 충분\]; 원문 직접 진입 경로이며 초기화 재실행 없음
관측 상위 상태는 코드가 아닌 실제 하위 상태를 포함한 composite. 가장 안쪽의 적용 가능한 전이가 우선한다.
보류 해제는 기기 대기 확인이며 업무 자동 재개가 아니다. 카메라 인식 불명만으로 센서 고장을 확정하지 않는다.
하위 전이가 우선해도 각 연결상실·보류 진입의 기록 보존 효과는 동일하게 적용한다. 이 기록 효과를 물리 정지 명령으로 해석하지 않는다.

대표 전이 축약도: 생략한 관측·복귀 전이의 원문은 JSON/대응표 보존. 최종 코드표와 함께 읽음.
직접 하위진입: UNKNOWN → COOKING : 상태 보고 \[현재 하위 상태 근거 충분\]; 원문 직접 진입 경로이며 초기화 재실행 없음
관측 상위 상태는 코드가 아닌 실제 하위 상태를 포함한 composite. 가장 안쪽의 적용 가능한 전이가 우선한다.
보류 해제는 기기 대기 확인이며 업무 자동 재개가 아니다. 카메라 인식 불명만으로 센서 고장을 확정하지 않는다.
하위 전이가 우선해도 각 연결상실·보류 진입의 기록 보존 효과는 동일하게 적용한다. 이 기록 효과를 물리 정지 명령으로 해석하지 않는다.

## 정상·복구·관측의 경계

T10은 RECOVERY\_CHECK에서 재가용을 확인한 뒤 IDLE로 가는 전이입니다. 복구 실패·불명은 현재 점검을 유지합니다. T09 운용 제외는 별도 제외 근거가 있어야 하며 실패 보고 자체와 같지 않습니다.

RETURNING·실제 CHARGING·기기 IDLE과 새 임무 배정 가능 여부는 구분합니다. 도착·도킹 접속 수락만으로 CHARGING을 확정하지 않습니다. 마지막으로 확인한 운용 제외·업무·물건·점유 기록은 연결 상실 후에도 보존하며 관측 회복만으로 제한을 자동 해제하지 않습니다.

A/B 공통 모형은 각 독립 기기에 적용합니다. Task Manager → Arm Master Controller → A/B Controller 경계를 따르며 Master의 최종 저장·승인 책임이나 새 API를 임의 확정하지 않습니다.

## 관측 책임과 미결정

조리대 실제 접시 배치와 적재·인계 결과의 확인은 필요하지만 상단·주방·서빙팔 카메라 중 어느 장치가 무엇을 확인할지는 미정입니다. 상단 관제의 AMR/테이블 관측, 의자 QR의 좌석·이용 종료 판단, 조리대 배치 확인은 목적과 관측 대상을 구분합니다.

미검출·가림·근거 불충분만으로 빈 테이블·정상 완료·SENSOR\_ERROR를 확정하지 않습니다. 실제 센서 고장과 업무 관측 불명을 구분합니다. 카메라 설치·시야·익힘 판정 채택·기준값·시간 제한·관측 유효성·중복 방지·재시도·최종 허용/승인 주체 및 API는 별도 합의 대상입니다.

## 검토 기준과 범위

Sequence Diagram V0.09(문서20), System Architecture21, 서비스 시나리오8, SR1을 대조한 문서 설계안입니다. 영업 준비와 마감은 독립 시퀀스이며 매장 영업 상태·기기 운용 상태·업무 객체의 완료를 구분합니다. 문서·도식 검토를 실물 동작·안전·익힘 시험 통과로 확대하지 않습니다.
