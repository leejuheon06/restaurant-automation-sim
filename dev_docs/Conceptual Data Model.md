## 1. 목적과 범위

State Diagram의 흐름(입장 → 배정·안내 → 주문 → 조리 → 픽업·적재·서빙 → 이용 종료·정리, 오류·복구)을 운영하려면 **무엇을 기록해야 하는지** 정한다. 테이블·컬럼 타입은 논리 데이터 모델에서 다룬다.

**범위 밖:** 결제, 회원, 재고, 통행 순서 결정(SR-035는 실시간 처리라 DB에 저장하지 않음)

## 2. 데이터 흐름 원칙

- DB는 **서버 PC 한 곳**(Docker MySQL 8.4)에만 둔다. **로봇에는 DB를 두지 않고, 로봇이 DB에 직접 접속하지도 않는다.**
- 상태는 State Diagram의 레인(주체)이 바꾼다. 손님·테이블·주문은 **서버/고객·테이블·주문 관리**, 임무·로봇·오류는 **서버/Service Workflow**.
- 로봇(ROS2)과 AI Server(HTTPS)는 보고만 하고, Workflow를 거쳐 저장된다. 위치·배터리처럼 잦은 값은 1초에 1번 또는 바뀔 때만 저장한다.
- 영상은 저장하지 않고 AI 판단 결과만 저장한다.

## 4. 관계

| 엔터티 | 관계 | 엔터티 | 규칙 |
| --- | --- | --- | --- |
| 테이블 | 1 : 0..1 | 위치 | 테이블마다 안내·서빙 위치 1개 |
| 테이블 | 1 : 0..N | 손님 그룹 | **진행 중(ASSIGNED, IN\_USE) 손님 그룹은 테이블당 1개** (SR-004, SR-031) |
| 손님 그룹 | 1 : 0..N | 주문 | 추가 주문 가능 |
| 주문 | 1 : 1..N | 주문 항목 | 항목은 메뉴 1개를 가리킴 |
| 손님 그룹 | 1 : 0..N | 임무(안내) | 가용 AMR이 없으면 대기(GUIDE\_PENDING) |
| 주문 항목 | 1 : 0..N | 임무(조리) | 메뉴별 조리 작업 (SR-014) |
| 주문 | 1 : 0..N | 임무(서빙) | 서빙 임무에 실린 주문 항목 1..N (SR-015, SR-018) |
| 로봇 | 1 : 0..N | 임무 | **로봇 1대에 진행 중 임무는 1건** |
| 임무 | 1 : 0..1 | 임무 | 관리자 중단 시 AMR 임무 재배정 (SR-034) |
| 로봇 / 임무 / 주문 | 1 : 0..N | 오류·복구 기록 | 장치·관련 임무·주문 기록 (SR-036) |
| 임무 | 1 : 0..N | AI 판단 결과 | 안내 중 손님 거리, 조리 중 익힘 |

## 5. State Diagram 장별 대응

| 장 | 흐름 | 생기거나 바뀌는 엔터티 |
| --- | --- | --- |
| 2. 입장·배정·안내 | CHECK\_IN → 대기/배정 → 안내 임무 → 동행 → 착석 | 손님 그룹, 테이블 상태, 안내 임무, AI 판단(손님 거리), 안내 예외 → 오류 기록 |
| 3. 주문 | 메뉴 선택 → 확정 → 주문 ID → 진행 상태 | 주문, 주문 항목 |
| 4. 조리 | 메뉴별 조리 → 익힘 판정 → 인계대 | 조리 임무, AI 판단(익힘), 주문 항목 서빙 준비 |
| 5. 픽업·서빙·복귀 | 서빙 임무 → 픽업 → 적재 → 테이블 → 수령 → 복귀·충전 | 서빙 임무, 주문 상태, 로봇 상태·충전 |
| 6. 이용 종료·정리 | 이용 종료 → 정리 대기 → 관리자 정리 완료 → 이용 가능 | 손님 그룹 종료, 테이블 상태 |
| 7. 오류·복구 | E\_STOP → 보류 → 복구 대기 → 재시도 또는 중단(재배정/주문 취소) | 오류·복구 기록, 임무·주문 보류, 재배정 임무 |

## 6. 팀 확인 사항

State Diagram의 "확인이 필요한 것"과 같은 항목이다. 11/13 상세설계 때 결정한다.

| # | 질문 | 지금 모델의 처리 | 결정되면 |
| --- | --- | --- | --- |
| Q1 | 로봇팔 대수: SA 3대 vs 배치도 2대(치킨·웍) | 로봇 수와 무관한 구조. 시드는 배치도 기준 2대 | 시드 데이터에서 로봇만 추가·삭제 |
| Q2 | 인계대 → AMR 적재 주체 (SR-021은 로봇팔) | 서빙 임무 중 로봇팔 상태 LOADING으로만 기록 | 적재를 별도 임무로 나누면 임무 유형 LOAD 추가 |
| Q3 | SR-026 로봇팔 테이블 전달 vs 손님 수령 확인 | 손님 확인/N초 후 자동 수령을 주문에 기록 | 로봇팔 전달이면 임무 유형 추가 |
| Q4 | 손님 대기 등록이 SR에 없음 (SA·맵에는 있음) | WAITING 상태와 대기 순번 유지 | SR에 추가하거나, 범위 밖이면 삭제 |
| Q5 | 기준값 N | 기준값 6개 등록, 값은 미정(NULL) | 값만 입력 |
