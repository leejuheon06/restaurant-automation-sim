## 읽는 법

상자는 해당 대상이 일정 조건을 유지하는 상태이고, 화살표는 사건 \[조건\] / 효과입니다. 사건은 업무 의미의 설계명이며 확정된 ROS2 메시지·API 이름이 아닙니다. 그림의 짧은 라벨은 바로 아래 전체 전이표와 함께 읽습니다.

검은 원은 초기 진입이며 사건·조건 없이 기본 상태로 진입합니다. 이중 원은 해당 유한 업무 객체의 완료입니다. 마름모는 확인이 끝난 뒤 즉시 조건을 평가하는 choice이며 응답을 기다리는 대기 상태가 아닙니다. 조건이 미충족·불명이면 보류합니다.

보류·실패와 취소 확정, 기기 복구와 업무 재개, 실제 전달과 로봇 복귀·충전·새 임무 가용을 구분합니다. 완료한 동작을 상태 진입으로 자동 재실행하지 않습니다. 연결 상실·관측 불명은 실제 물리 정지 또는 장비 고장의 증거가 아닙니다.

## 이번 보강

음식이 실제 AMR에 적재된 뒤 테이블로 출발하기 전의 LOADED 상태를 분리했습니다. 정상 장비의 업무 실패도 해당 업무 객체의 보류 사건에 포함하고, 실제 전달 완료 뒤 복귀 실패가 완료 사실을 되돌리지 않도록 경계를 명시했습니다.

LOADED 등 이 페이지의 이름은 업무 객체 상태의 개념 식별자입니다. 기기 공통 STA 코드를 추가하거나 실제 네트워크 열거형을 확정한 것이 아닙니다. 네 그림은 핵심 실행 대상의 범위이며 매장·방문·테이블 전체 생명주기, 화면별 처리 상태 전체를 확정하지 않습니다.

| 실제 전달 후 복귀/도킹/충전 실패 | 전달·완료 사실 유지; 로봇 복귀·충전·새 임무 가용만 별도 미확정 |
| 장비는 정상이나 음식/인계 작업 실패 | 기기 고장으로 단정하지 않고 영향 업무 객체의 실패·보류로 관리 |
| 장비 복구 성공·중단 업무 결과 불명 | 업무 보류 유지; 확인점·실제 결과·허용 확인 후 남은 범위만 재개 |

복수 음식이 서로 다른 단계일 때의 주문 집계 우선순위·부분/전량 취소, 조리 FAILED 확정·재시도/새 시도 정책은 미정입니다. 대표 상태를 모든 음식의 동시 진행으로 해석하지 않습니다.

## 관측 책임과 미결정

조리대 실제 접시 배치와 적재·인계 결과의 확인은 필요하지만 상단·주방·서빙팔 카메라 중 어느 장치가 무엇을 확인할지는 미정입니다. 상단 관제의 AMR/테이블 관측, 의자 QR의 좌석·이용 종료 판단, 조리대 배치 확인은 목적과 관측 대상을 구분합니다.

미검출·가림·근거 불충분만으로 빈 테이블·정상 완료·SENSOR\_ERROR를 확정하지 않습니다. 실제 센서 고장과 업무 관측 불명을 구분합니다. 카메라 설치·시야·익힘 판정 채택·기준값·시간 제한·관측 유효성·중복 방지·재시도·최종 허용/승인 주체 및 API는 별도 합의 대상입니다.

## 검토 기준과 범위

Sequence Diagram V0.09(문서20), System Architecture21, 서비스 시나리오8, SR1을 대조한 문서 설계안입니다. 영업 준비와 마감은 독립 시퀀스이며 매장 영업 상태·기기 운용 상태·업무 객체의 완료를 구분합니다. 문서·도식 검토를 실물 동작·안전·익힘 시험 통과로 확대하지 않습니다.
