# Sequence Diagram V0\.09

# 서비스 시퀀스 다이어그램

정상·실패·결과 미확정·복구 후 재개를 구분한 논리 설계안입니다. 구현 완료 또는 실제 기기의 시험 결과를 의미하지 않습니다. 미정인 인터페이스·관측 기준·운영 정책은 TBD로 표시했습니다.

## 이번 변경

서빙 픽업·테이블 이동·공통 복귀의 Navigator 요청/결과를 보강했습니다. 실제 정차·적재·인계·회수 완료 근거가 확인되기 전에는 후속 동작을 진행하지 않습니다. 실패·불명 시 중단, 완료 동작 중복 실행 방지, 미완료 작업 재개·재배정과 관리자 개입을 함께 정리했습니다.

영업 준비와 영업 마감을 독립적인 시퀀스로 분리했습니다. 주요 서비스 14개와 공통·상세·관리자 상호작용 7개를 정의합니다. 참여자는 업무 경계에 따라 배정하며 인원 수 제한을 적용하지 않습니다.

| 표기 | 의미 |

| 실선·열린 화살촉 | 논리 요청·보고 후보. 최종 ROS2 메시지/API 동기·비동기 계약은 별도 확정 대상입니다. |

| break | guard가 참이면 해당 break가 속한 구획의 나머지를 중단합니다. 최상위 break는 상호작용을 종료하고, 6번의 운용 구획 내부 break는 그 구획을 종료한 뒤 공통 결과 통지로 이어집니다. 별도 ref 안의 중단은 호출자 전체를 자동 중단하지 않으므로 호출자가 결과를 확인합니다. |
| ref | 실제로 정의된 상세 상호작용의 재사용. 각 그림 아래 진입·성공·실패·반환 지점 계약과 대상 도식을 함께 봅니다. |
| 내부 처리 \[역할\] | 그 역할의 내부 대조·판정. 외부 역할로 보낸 네트워크 메시지가 아닙니다. |

## 01 · 영업 준비

범위: 기기가 정상 동작한다는 (가정) 아래 준비·가용 근거를 확인하는 영업 시작 조율. 실제 주행·시주행·마감 절차를 실행하지 않는다. 점검 보고 인터페이스는 설계 후보/TBD.

진입: 관리자의 영업 시작 요청. 정상 동작 가정과 실제 준비 보고 검증을 구분. / 성공: 필요한 준비·가용 근거가 확인된 경우 영업 시작 결과를 표시. / 실패·불명: 준비 실패·결과 불명·미수신이면 영업 시작 성공을 확정하지 않고 사유를 표시.

## 06 · 음식 서빙과 복귀

흐름: 서빙 준비·배정 → 픽업 위치 이동·정차 → 음식 적재 → 테이블 이동·정차 → 실제 음식 전달 → 복귀 이동 → 도킹·실제 충전·재가용 확인.

Navigator의 세 이동 구간과 부착팔의 적재·전달을 이 그림 안에서 직접 확인합니다. 각 단계의 실패·불명 조건에서는 운용 구획의 나머지를 중단하고, 아래 공통 결과 통지로 이어집니다. 실제 전달 완료와 복귀·충전·가용 여부는 구분합니다.

범위: 같은 음식의 서빙 준비·픽업·적재·테이블 이동·실제 전달·복귀·도킹·충전·재가용을 한 도식에서 추적한다. 단계별 break는 운용 구획을 중단하고 하단 공통 결과 통지로 이어진다.

## 공통·상세·관리자 도식

아래 도식은 별도의 신규 서비스가 아니라 본문 흐름의 재사용·상세 정의입니다. 필요한 항목을 펼쳐 확인합니다. ref 호출은 해당 상세를 한 번 수행하는 의미이며 개요와 상세를 중복 실행하지 않습니다.

범위: 복귀 요청 한 번·통행 허용→주행→도착/정차→도킹/충전/가용 개별 근거. N은 충전 판정자가 아님.

## 상태도와의 대응

현재 기기별 상태도의 T10은 RECOVERY\_CHECK → 정상 영역의 기본 진입 → IDLE입니다. 기존 작업을 자동 재개한다는 뜻이 아닙니다. T13은 기기 모델마다 다른 전이입니다: 화면 모델 OPERATING → FAULT\_HANDLING, AMR 모델 ARM\_OPERATING → IDLE, 주방 팔 모델 IDLE → ARM\_OPERATING. 번호만으로 서로 같은 의미라고 해석하지 않습니다.
