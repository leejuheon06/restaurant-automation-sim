## 4. Confluence 기준으로 코드를 고치길 권하는 것

### 4.1 요청 키와 조작 ID (01, 04, 05, 07, 08, 14~17, 19, 20)

| | Confluence v0.2 | 코드 |
| --- | --- | --- |

| 코드의 문제 | | `web_service`가 4초 뒤 "응답 없음"을 돌려줘도 보낸 요청은 취소되지 않음. 화면에서 다시 누르면 주문·임무가 두 번 들어가거나, 실패로 보인 `RESUME`이 나중에 처리될 수 있음(코드 리뷰 R16-46, 미수정) |

- 권고: **C→코드.** 실제로 일어날 수 있는 결함을 막는 항목이고 관제 PC 안에서 끝납니다.

- 순서 제안: 주문(04·15)과 관리자 조작(07·17)부터. 접수(01·14)와 종료(05·16)는 그다음.

### 4.2 접수·거절·사유 구분 (19, 그리고 14·15·16의 `status`/`disposition`)

- 코드의 문제: 관제가 임무를 거절하면 오류 로그만 남고 업무 상태에 반영되지 않아, 음식이 `READY`에, 테이블이 `COLLECTING`에 머뭅니다(R16-10, 미수정).
- 권고: **C→코드.** `bool` 하나 대신 접수·대기·거절과 사유 코드를 돌려주고, `central_control`이 거절을 업무 상태에 반영하게 합니다. 비용은 작습니다.

### 4.6 구조는 코드, 항목은 Confluence (합침)

**화면 상태(06, 31).** 코드의 "0.25초마다 전체 스냅샷"은 누락 복구가 필요 없어 단순하고, 화면 몇 개 규모에서는 충분합니다. v0.2의 변경 발행 + 버전 + 조회 서비스는 대역을 아끼지만 구현이 큽니다. 권고는 구조는 코드 그대로 두고, 스냅샷에 버전과 기준 시각 키를 더하는 것입니다(비용 작음). Confluence에는 "전체 스냅샷, 0.25초"로 적습니다.

**방문 종료(05, 16).** v0.2의 방문 ID 기준은 다른 방문을 잘못 끝내는 일을 막습니다. 코드의 테이블 기준은 의자 QR 판정(`source=QR`)처럼 방문 ID를 모르는 경로에 맞습니다. 권고는 테이블 번호를 유지하되 화면에서 오는 요청에는 방문 ID를 함께 받아 대조하고, 응답에 회수 필요 여부를 더하는 것입니다.

**장치 이벤트(34).** 코드의 주기 상태 보고(`RobotStatus.error`, `/fleet/arm_status`)는 한 번 유실돼도 다음 주기에 복구됩니다. v0.2의 이벤트 토픽은 유실되면 따로 대조해야 합니다. 조리 팔이 마스터를 거치지 않고 관제에 직접 보고하는 것도 마스터가 죽었을 때 팔 상태가 보인다는 점에서 낫습니다. 다만 코드는 `ArmStatus.error`가 항상 빈 값이고, 실물 서빙 팔의 끊김·오류가 작업 결과로만 전달됩니다. 권고는 구조는 코드로 두고(Confluence 수정), 팔 오류를 `ArmStatus.error`에 채우는 것입니다(코드 수정).

**비상 정지(35~37).** 코드의 생존 신호(`/fms/heartbeat`, 5 Hz, 정지 목록 포함)는 통신이 끊기면 로봇이 스스로 서고, 반복 발행이라 유실에 강합니다. v0.2의 서비스 3개는 "요청 접수"와 "실제 정지 확인", "재가동 승인"을 구분하고 기록을 남기는 점이 낫습니다. 권고는 채널은 코드로 두고(Confluence 수정), 다음을 코드에 더하는 것입니다.

- 서빙 팔 구동부와 조리 팔이 생존 신호를 직접 듣게 함. 지금은 `mobile_controller`가 죽으면 팔이 멈추지 않습니다(R16-26, 안전).
- `RESUME`에 승인자와 시각을 실행 로그에 남김.
- 정지 확인은 지금처럼 상태 보고의 `E_STOP`으로 읽되, Confluence 36번을 "33번 상태 보고로 확인"으로 적음.

**실행 재조회(21, 44).** 코드는 서비스 없이 `plan_version`과 세션으로 옛 실행을 거릅니다. 서비스를 새로 만드는 것보다, 지금 있는 결함 두 개를 고치는 것이 같은 목적에 더 직접 닿습니다. 경로 결과의 도달 위치를 쓰지 않는 것(R16-02)과 임무를 떼어 낸 뒤 로봇이 옛 목적지로 다시 갈 수 있는 것(R16-01, 안전)입니다. Confluence에는 "22·24·32·33으로 대조, 별도 서비스 없음"으로 적습니다.
