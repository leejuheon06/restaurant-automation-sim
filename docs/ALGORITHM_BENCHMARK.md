# 알고리즘 조합 비교 결과

> **이름 변경 (2026-11-13):** 배정 스케줄러 `min_cost`, `min_cost_eta`, `min_cost_eta_rh`는 이전에 `hungarian`, `hungarian_eta`, `hungarian_eta_rh`라고 불렀습니다. 이 스케줄러들은 배정 문제의 최적해를 구할 뿐 헝가리안 방법(Kuhn 1955)을 구현하지 않으므로 이름을 바꿨습니다. 알고리즘과 수치는 그대로이며, 원시 기록(CSV, Gazebo 로그)에는 옛 이름이 남아 있습니다.

> 이 문서는 테이블 지점 변경 전 배치 기준의 1차 비교입니다. 현재 배치 기준의 최종 선정 보고서는 [ALGORITHM_SELECTION_REPORT.md](ALGORITHM_SELECTION_REPORT.md)입니다.

배정(스케줄러) 5종 × 경로 계획(플래너) 4종 = 20개 조합을 `fleet_bench`로 비교했습니다.

- 실행일: 2026-11-12, 가운데 4인석 회전·양쪽 접근 및 양보 후진 수정 반영 후
- 방법: ROS·Gazebo 없이 Task Manager 코어만 고속 실행하는 오프라인 시뮬레이션. 시나리오 3종(`normal`, `rush`, `bottleneck`) × 시드 3개(손님 도착 ±4초) 평균
- 원본: [bench_normal.csv](bench_normal.csv), [bench_rush.csv](bench_rush.csv), [bench_bottleneck.csv](bench_bottleneck.csv)
- 재실행: `ros2 run frybot_control fleet_bench --scenario rush --seeds 3 --csv out.csv`

## 결론

**권장 조합: `min_cost_eta_rh` + `sipp`**

- 세 시나리오 9회 모두 완료했고, 주문→전달 시간이 1위 조합과 0.5~4 % 차이.
- 계획 시간이 0.25~0.30 ms로 `ccbs`(3~6 ms)의 약 1/15.
- 로봇 간 최소 간격이 항상 안전거리(0.155 m) 이상.

`min_cost_eta_rh` + `ccbs`는 전달 시간이 가장 짧지만(권장 조합보다 0.5~4 % 빠름) 계획 시간이 길고 점유 대기가 조금 더 생깁니다. 로봇이 3대인 지금은 이득이 작습니다.

이전 기본값 `min_cost` + `sipp`는 `bottleneck`에서 3회 중 1회를 끝내지 못했습니다. **2026-11-12에 기본값을 권장 조합 `min_cost_eta_rh` + `sipp`로 변경했습니다**(런치 인자, Task Manager 파라미터, `DEFAULT_SCHEDULER`).

## 주의할 결과

- **완료하지 못한 조합:** `min_cost`+`sipp`(bottleneck 2/3), `min_cost_eta`+`cooperative_astar`·`fifo_nearest`+`cooperative_astar`·`fifo_nearest`+`independent_astar`·`priority_greedy`+`independent_astar`(normal 2/3). 원인은 아직 분석하지 않았습니다.
- **최소 간격 0.149 m:** `normal`의 `min_cost`+`ccbs`, `priority_greedy`+`ccbs`와 `independent_astar` 일부에서 안전거리 0.155 m보다 6 mm 가깝게 접근했습니다.
- **한계:** 오프라인 시뮬레이션은 로봇을 노드 사이 직선으로 움직입니다. Nav2 주행 지연, 제자리 회전, 후진 속도 차이는 반영되지 않습니다. Gazebo에서는 같은 순위가 나오는지 확인하지 않았습니다.
