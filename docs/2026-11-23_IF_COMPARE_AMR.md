## 먼저 한 줄로

정의서(팀이 쓴 설계 문서)와 코드(지금 만든 프로그램)가 서로 다르게 되어 있습니다. 그래서 둘로 나눴습니다.

- **정의서가 더 좋은 것**: 코드를 정의서에 맞게 고칩니다.
- **코드가 더 좋은 것**: 정의서에 코드 내용을 적어 넣습니다.

비유하면 관제는 교통경찰, AMR은 배달 로봇, 서빙 팔은 로봇 위에 달린 팔입니다.

## 2. 코드가 더 좋은 것 (정의서에 적어 넣습니다)

### 22번: 길 허락받는 방법

- **정의서**: 로봇이 경찰에게 "지나가도 돼요?" 하고 매번 물어봅니다(`RequestPassage` 서비스).
- **코드**: 경찰이 0.5초마다 "너는 여기까지 가도 돼"라고 계속 알려 줍니다(`TrafficGrant` 토픽).
- **코드가 좋은 이유**: 말이 한 번 안 들려도 0.5초 뒤에 또 들립니다. 허락을 못 들으면 로봇은 그냥 서 있습니다.
- 통합 문서 4절도 지금의 토픽 방식을 "기준선"으로 적어 두었습니다. 22번 페이지와 I/F 목록만 아직 서비스로 남아 있습니다.

정의서에 적을 내용:

| 칸 | 적을 말 |
| --- | --- |
| 이름 | `TrafficGrant` (통행 허가) |
| 종류 | 토픽 (계속 알려 주는 방식) |
| 누가 누구에게 | 관제 → 로봇 |
| 주소 | `/fms/traffic_grant` |
| 얼마나 자주 | 0.5초마다 |
| 담긴 내용 | 로봇 이름(`robot_id`), 일 번호(`task_id`), 경로 번호(`plan_version`), 어디까지 가도 되는지(`granted_index`) |
| 규칙 | 허락받은 곳까지만 갑니다. 허락이 없으면 섭니다. 옛 경로의 허락은 버립니다. |

### 23~26번: 안내·서빙·그릇 회수·충전하러 가기

- **정의서**: 로봇에게 "3번 테이블에 서빙해"라고 한 번에 시킵니다(`GuideGuest`, `ServeFood`, `CollectDishes`, `ReturnToCharge`).
- **코드**: 경찰이 일을 잘게 나눠서 "여기로 가", "실어", "저기로 가", "내려"를 하나씩 시킵니다(`NavigateRoute` + `ArmJob`).
- **코드가 좋은 이유**: 길이 로봇 한 대만 지나갈 만큼 좁습니다. 하나씩 시켜야 마주쳤을 때 "잠깐 비켜"라고 중간에 말할 수 있습니다.

정의서에는 "로봇에게 보내는 명령" 목록에서 빼고, 아래 순서표로 적습니다.

| 일 | 관제가 시키는 순서 |
| --- | --- |
| 안내 (23) | 입구로 가기 → 손님을 보며 뒤로 테이블까지 가기 |
| 서빙 (24) | 음식 받는 곳으로 가기 → 싣기 → 테이블로 가기 → 내리기 |
| 그릇 회수 (25) | 테이블로 가기 → 그릇 싣기 → 퇴식구로 가기 → 그릇 내리기 |
| 충전하러 가기 (26) | 자기 자리(홈)로 가기 |


### 새로 적을 것 1: "이 길로 가" 명령

개별 정의서(번호)가 없어서 새로 적어야 합니다.

| 칸 | 적을 말 |
| --- | --- |
| 이름 | `NavigateRoute` (경로 따라가기) |
| 종류 | 액션 (오래 걸리는 일을 시키고 중간 보고를 받는 방식) |
| 누가 누구에게 | 관제 → 로봇 |
| 주소 | `/{로봇 이름}/navigate_route` |
| 시킬 때 주는 것 | 일 번호(`task_id`), 경로 번호(`plan_version`), 가는 방식(`mode`: NORMAL·GUIDE·YIELD), 손님 번호(`visit_id`), 지나갈 지점 목록(`route`) |
| 중간 보고 | 지금 몇 번째 지점까지 왔는지(`reached_index`) |
| 끝났을 때 | 성공했는지, 어디까지 갔는지, 이유(`reason`: OK·PREEMPTED·CANCELED·GUEST_LOST·NAV2_FAILED·E_STOP·FMS_RESTART·NO_PROGRESS) |
| 규칙 | 새 경로가 오면 하던 경로는 그만둡니다. |

### 새로 적을 것 2 + 28번: 팔에게 일 시키기

- **정의서(28번)**: "이 물건을 여기서 저기로 옮겨"처럼 물건과 위치를 알려 줍니다(`TransferObject`).
- **코드**: "싣기", "내리기"처럼 일 이름만 알려 줍니다. 팔은 미리 정해 둔 자세로 움직입니다(`ArmJob`).
- **코드가 좋은 이유**: 지금 실제 팔은 정해 둔 자세만 쓰기 때문에 물건·위치를 받아도 쓸 곳이 없습니다.

| 칸 | 적을 말 |
| --- | --- |
| 이름 | `ArmJob` (팔 작업) |
| 종류 | 액션 |
| 누가 누구에게 | ① 관제 → 로봇 ② 로봇 → 서빙 팔 |
| 주소 | ① `/{로봇 이름}/arm_job` ② `/{로봇 이름}/serving_arm/arm_job` |
| 시킬 때 주는 것 | 일 번호(`task_id`), 팔 이름(`arm_id`), 일 종류(`job`: HOME·LOAD·UNLOAD·COLLECT_DISHES·RETURN_DISHES), 계획 시간(`duration`), 테이블 번호와 메뉴(`params_json`) |
| 중간 보고 | 얼마나 진행됐는지(`progress`, 0~1) |
| 끝났을 때 | 성공했는지, 이유(`reason`: OK·CANCELED·E_STOP·ARM_OFFLINE·REJECTED·NO_POSE·ARM_TIMEOUT) |
| 규칙 | 잘 끝나면 팔을 접습니다. 취소되거나 문제가 생기면 그 자리에 멈춥니다. |

물건·위치는 "나중에 추가할 수 있는 항목"으로 적어 두면 됩니다.

### 34번에 35·41·48번을 합치기: 로봇 상태 알림

- **정의서**: 상태 알림(34), 사고 알림(35), 안전 상태 물어보기(41), 스스로 점검(48)이 따로 있습니다.
- **코드**: 로봇이 1초에 10번, 한 장짜리 보고서에 전부 적어 보냅니다(`RobotStatus`).
- **코드가 좋은 이유**: 한 번 놓쳐도 0.1초 뒤에 다음 보고가 옵니다. 사고 알림은 한 번 놓치면 그대로 사라집니다.

| 칸 | 적을 말 |
| --- | --- |
| 이름 | `RobotStatus` (정의서 이름은 `MobileStatus`) |
| 종류 | 토픽 |
| 누가 누구에게 | 로봇 → 관제 |
| 주소 | `/fleet/robot_status` (모든 로봇이 같은 곳에 보내고, 로봇 이름으로 구분) |
| 얼마나 자주 | 1초에 10번 |
| 담긴 내용 | 로봇 이름, 하는 일(`state`), 위치와 방향(`x`·`y`·`yaw`), 배터리(0~100), 충전 중인지, 일 번호, 경로 번호, 마지막으로 도착한 지점, 팔 상태, 문제 이름(`error`) |
| 35번 자리 | 문제 이름 칸: COMMUNICATION_ERROR(통신 끊김), EMERGENCY_STOP(비상 정지), DRIVE_ERROR(주행 실패), SENSOR_ERROR(위치 센서 이상), SELF_CHECK_ERROR(시작 점검 실패) |
| 41번 자리 | 하는 일 칸이 E_STOP이면 멈춘 것 |
| 48번 자리 | 하는 일 칸이 LOCALIZING(위치 찾는 중) 또는 NOT_LOCALIZED(위치 못 찾음) |
| 규칙 | 보고가 2초 넘게 안 오면 관제는 그 로봇에게 새 허락을 주지 않습니다. |

### 새로 적을 것 4: 관제가 살아 있다는 신호와 비상 정지

가장 먼저 적어야 하는 항목입니다.

- **정의서(40~42번)**: 로봇에게 "멈춰"라고 전화를 겁니다(서비스). 통신이 끊기면 전화가 안 걸립니다.
- **코드**: 관제가 1초에 5번 "나 살아 있어"라고 방송합니다. 방송이 2초 넘게 안 들리면 로봇이 스스로 섭니다(`FleetHeartbeat`).
- **코드가 좋은 이유**: 통신이 끊겨도 로봇이 멈춥니다.
- 통합 문서 7절은 진짜 비상 정지 버튼은 현장 안전 회로가 맡는다고 적었습니다. Pinky와 서빙 팔에 그런 회로가 있는지는 확인 필요입니다.

| 칸 | 적을 말 |
| --- | --- |
| 이름 | `FleetHeartbeat` (관제 생존 신호) |
| 종류 | 토픽 |
| 누가 누구에게 | 관제 → 모든 로봇 |
| 주소 | `/fms/heartbeat` |
| 얼마나 자주 | 1초에 5번 |
| 담긴 내용 | 보낸 시각(`stamp`), 관제를 켤 때마다 바뀌는 번호(`session`), 지금 멈춰 있어야 하는 로봇 목록(`estop`) |
| 규칙 | 2초 넘게 안 들리면 로봇은 섭니다. 목록에 든 로봇은 바퀴와 팔을 멈춥니다. 관제 번호가 바뀌면 옛 허락과 경로를 버립니다. |
| 40~42번과 연결 | 40번 "멈춰"는 이 목록에 넣는 것입니다. 정말 멈췄는지는 로봇 상태 알림으로 확인합니다. 42번 "다시 움직여도 돼"는 목록에서 빼는 것이고, 누가 왜 뺐는지 적습니다. |
